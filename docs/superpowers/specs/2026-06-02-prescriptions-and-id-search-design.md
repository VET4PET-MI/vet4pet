# אפיון: מרשמים/מסמכים + הזדהות לפי ת"ז

תאריך: 2026-06-02
סטטוס: מאושר לעיצוב, ממתין לאישור אפיון כתוב
היקף: `web-app/` + `backend/` בלבד (לא נוגעים ב-`android-app/`)

## רקע ומטרה

שתי תוספות לאתר Vet4Pet:

1. **הזדהות לפי ת"ז** — לאפשר לווטרינר לחפש חיה לפי תעודת זהות אמיתית של הבעלים + שם החיה.
2. **טאב מרשמים/מסמכים** — אזור ייעודי בפרופיל החיה למרשמים ולמסמכים, נפרד מההיסטוריה הרפואית הקלינית.

### מה כבר קיים (ולא נבנה מחדש)

- **מערכת רשומות רפואיות מלאה** (`MedicalRecord`): הווטרינר מוסיף רשומה, מצרף קובץ (PDF/תמונה) דרך `POST /api/upload`, והבעלים צופה ומוריד בעמוד `PetProfile`. סוגים קיימים: `VISIT_SUMMARY, VACCINATION, LAB_RESULT, XRAY, BLOOD_TEST, CONSULTATION, OTHER`.
- **חיפוש בדאשבורד הווטרינר** (`Dashboard.jsx` → `VetDashboard`): שדות "ת"ז בעלים" + "שם חיה" קיימים בUI.

### הבעיה שהאפיון פותר

ה-"ownerId" שמשמש כיום לחיפוש הוא ה-`_id` הפנימי של MongoDB (`Pet.ownerId` = `req.user.id`) — מחרוזת hex שהבעלים לא מכיר והווטרינר לא יכול להשיג. אין שדה ת"ז כלל ב-`User`. לכן החיפוש הקיים אינו שמיש בפועל, והאפיון מחליף אותו בהזדהות אמיתית.

## פיצ'ר 1 — הזדהות לפי ת"ז

### מודל נתונים

`backend/models/User.js` — שדה חדש:

```js
nationalId: { type: String, trim: true, default: undefined }
```

אינדקס ייחודי ודליל כדי לא לשבור בעלים קיימים נטולי ת"ז ולמנוע כפילויות:

```js
userSchema.index({ nationalId: 1 }, { unique: true, sparse: true });
```

הערה: ל-`sparse unique` חשוב ש-`nationalId` יהיה `undefined` (לא `''` או `null`) כשאינו קיים, אחרת ערך ריק יחיד "יתפוס" את האינדקס. ב-register נשמור את השדה רק אם הוזן ערך תקין.

### ולידציה

פונקציית עזר משותפת (backend) `isValidIsraeliId(id)`:
- בדיוק 9 ספרות (עם השלמת אפסים מובילים אם קצר מ-9 — סטנדרט ת"ז ישראלי).
- בדיקת ספרת ביקורת (אלגוריתם Luhn הישראלי).
- מחזירה את הת"ז המנורמלת (9 ספרות) או `null`.

### Backend — register

`controllers/authController.js` → `register`:
- מקבל `nationalId` מה-body.
- אם `role === 'owner'`: ת"ז **חובה**; אם חסרה/לא תקינה → `400` עם הודעה ברורה.
- אם `role === 'vet'`: מתעלמים מ-`nationalId` (לא רלוונטי).
- בדיקת כפילות לפני יצירה: אם קיים משתמש עם אותה `nationalId` → `409` "תעודת זהות כבר רשומה במערכת".
- שומרים את הת"ז המנורמלת על המשתמש.
- **פרטיות:** `nationalId` **לא** נכלל ב-JWT ולא ב-`sanitize(user)` שחוזר ללקוח. נשאר רק בצד שרת לצורך חיפוש.

### Backend — חיפוש חיה

`controllers/petController.js` → `getPets`:
- כיום מקבל `ownerId, name`. נחליף את הסמנטיקה של חיפוש הווטרינר ל-`nationalId`:
  - אם `req.user.role === 'vet'` ו-`nationalId` סופק:
    1. נרמול + ולידציה של הת"ז.
    2. `User.findOne({ nationalId, role: 'owner' })`.
    3. אם לא נמצא בעלים → מחזירים מערך ריק (לא שגיאה).
    4. אם נמצא → `filter.ownerId = user._id.toString()`.
  - `name` ממשיך לעבוד כ-`$regex` (case-insensitive), וניתן לחפש לפיו לבד.
- בעלים (`role === 'owner'`) — ללא שינוי: רואה רק את החיות שלו.
- **תאימות לאחור:** הפרמטר הישן `ownerId` יוסר מנתיב הווטרינר; אין צרכן חיצוני שמסתמך עליו מלבד הדאשבורד שמתעדכן באותו PR.

### Frontend

**`pages/Register.jsx`:**
- שדה ת"ז חדש, מוצג **רק** כשהטאב הוא `owner`.
- ולידציה בצד לקוח לפני שליחה (9 ספרות; הודעת שגיאה מתורגמת).
- נשלח כ-`nationalId` ב-body של ההרשמה.

**`pages/Dashboard.jsx` → `VetDashboard`:**
- שדה "ת"ז בעלים" הקיים נשלח כעת כ-`nationalId` (במקום `ownerId`).
- שאר לוגיקת החיפוש/תצוגה ללא שינוי.

**i18n:** מפתחות חדשים ב-`web-app/src/i18n/i18n.js` (he + en): תווית ת"ז, placeholder, והודעות שגיאה (ת"ז לא תקינה / כבר רשומה).

## פיצ'ר 2 — טאב מרשמים/מסמכים

### מודל נתונים

`backend/models/MedicalRecord.js` — הרחבת ה-enum:

```js
const RECORD_TYPES = [
  'VISIT_SUMMARY', 'VACCINATION', 'LAB_RESULT', 'XRAY',
  'BLOOD_TEST', 'CONSULTATION', 'PRESCRIPTION', 'OTHER',
];
```

נוסף סוג `PRESCRIPTION` ("מרשם"). הסוג הגנרי `OTHER` ("מסמך/אחר") כבר קיים. אין שדות חדשים — מרשם משתמש באותם שדות (`findings` לטקסט, `fileUrl` לקובץ מצורף).

### קטגוריזציה לטאבים

מגדירים שתי קבוצות סוגים (קבוע משותף בצד לקוח, ובסינון השרת):

- **היסטוריה רפואית:** `VISIT_SUMMARY, VACCINATION, LAB_RESULT, XRAY, BLOOD_TEST, CONSULTATION`
- **מרשמים ומסמכים:** `PRESCRIPTION, OTHER`

### Backend — סינון לפי סוג עם pagination

`controllers/medicalRecordController.js` → `getRecordsByPet`:
- פרמטר query אופציונלי חדש `types` (רשימה מופרדת בפסיקים).
- אם סופק: `filter.type = { $in: types.split(',') }`.
- אם לא סופק: התנהגות נוכחית (כל הסוגים) — שומר תאימות לאחור.
- ה-pagination (`skip`/`limit`/`total`/`hasMore`) פועל על הקבוצה המסוננת, כך ש"טען עוד" נכון בכל טאב.

### Frontend — `pages/PetProfile.jsx`

- **מתג טאבים** מעל אזור הרשומות: **"היסטוריה רפואית"** | **"מרשמים ומסמכים"**.
- כל טאב מנהל את הרשומות/pagination שלו ומושך עם `types` המתאים. מעבר בין טאבים טוען את הקבוצה הרלוונטית (איפוס skip).
- `RECORD_TYPE_DEFS` — הוספת `PRESCRIPTION`: `key: 'prescription'`, אייקון `💊`, צבע ייעודי (לדוגמה סגול/אינדיגו).
- **הוספת רשומה:** הכפתור "הוסף רשומה" עדיין פותח את `AddRecordModal`. כשהמודל נפתח מתוך טאב המרשמים — סוג ברירת המחדל הוא `PRESCRIPTION`. אחרי שמירה, מרעננים את הטאב הפעיל.
- מצב ריק (empty state) מותאם לכל טאב (טקסט שונה ל"אין מרשמים" מול "אין היסטוריה רפואית").
- **בעלים (readOnly):** רואה את שני הטאבים, צופה ומוריד, ללא הוספה — כמו ההתנהגות הקיימת.

**i18n:** מפתחות חדשים — שמות הטאבים, `petProfile.types.prescription`, וטקסטים של מצב ריק לכל טאב.

## זרימת נתונים

**הרשמת בעלים:** טופס Register (+ת"ז) → `POST /api/auth/register` → ולידציה + בדיקת כפילות → שמירת `nationalId` על `User`.

**חיפוש ווטרינר:** Dashboard (ת"ז + שם) → `GET /api/pets?nationalId=…&name=…` → `User.findOne({nationalId})` → `Pet.find({ownerId: user._id, name: /…/i})` → כרטיסי חיות.

**מרשם/מסמך:** PetProfile טאב מרשמים → `AddRecordModal` (type=PRESCRIPTION, +קובץ אופציונלי) → `POST /api/upload` (אם יש קובץ) → `POST /api/records` → תצוגה בטאב.

**צפייה בטאב:** PetProfile → `GET /api/records/pet/:petId?types=PRESCRIPTION,OTHER&limit&skip` → רשימה ממוינת + "טען עוד".

## טיפול בשגיאות

- ת"ז לא תקינה בהרשמה → `400`, הודעה מתורגמת ליד השדה.
- ת"ז כפולה → `409`, הודעה מתורגמת.
- חיפוש ת"ז ללא תוצאה → מערך ריק + מצב "לא נמצאו תוצאות" קיים (לא שגיאה).
- כשל העלאת קובץ/שמירת רשומה → הודעת שגיאה קיימת ב-`AddRecordModal`.

## בדיקות

- **ולידציית ת"ז (backend, unit):** ת"ז תקינות/לא תקינות, השלמת אפסים, ספרת ביקורת.
- **register (integration):** בעלים ללא ת"ז → 400; ת"ז כפולה → 409; ת"ז תקינה → 201 ו-`nationalId` לא חוזר ללקוח.
- **getPets (integration):** ווטרינר מחפש ת"ז קיימת → מקבל את חיות הבעלים; ת"ז לא קיימת → ריק; בעלים מוגבל לחיות שלו.
- **getRecordsByPet (integration):** סינון `types` מחזיר רק את הסוגים המבוקשים עם pagination נכון; ללא `types` מחזיר הכל.
- **ידני (UI):** הרשמת בעלים עם ת"ז → חיפוש מהדאשבורד → פתיחת פרופיל → הוספת מרשם עם קובץ → מעבר בין הטאבים → בדיקת תצוגה אצל הבעלים (readOnly).
